# Progress Reports

Status
- Purpose: Chronicle major accomplishments between pull requests or milestones
- Format: `YYYY-MM-DD-<short-label>.md`
- Audience: Internal team, external stakeholders, PR descriptions
- Retention: Keep all reports; they provide valuable historical context

## Guidelines

1. **Create a new report** whenever a significant milestone is completed (major feature, bug fix, architectural decision)
2. **Summarize accomplishments** since the prior report in these categories:
   - Planning & design decisions
   - Core functionality implemented
   - Testing & validation work
   - Documentation & tooling
   - Known issues or blockers
3. **Link to relevant docs** (PRs, issue numbers, planning documents) when helpful
4. **Do NOT delete** older reports—they remain useful for historical context and understanding project evolution
