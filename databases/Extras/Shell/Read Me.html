Frontier 9.5: Calling Frontier from the Shell

Frontier for OS X is a bridge between the Macintosh and UNIX worlds.

One side of that bridge is sys.unixShellCommand, which allows Frontier to call into a shell.

The other side of that bridge is calling Frontier from the command line.

Here's a screen shot.

Installation

Copy the mini-application named frontier that's in this folder into your home directory or into /usr/bin.

How to use it

Launch Terminal.

Call one of the example scripts this way: /path/to/frontier examples.getStateName 41

("/path/to/frontier" should be the path to the mini-app named frontier that you just installed.)

Type return -- you should see "South Dakota" returned.

Errors go to stderr

If a script generates an error, or if there's a communication error, the error message is directed to stderr.

Where scripts live

In Frontier, jump to user.unix.scripts.

It's a table much like user.betty.rpcHandlers or user.soap.rpcHandlers. The first command-line argument identifies a script. Any addresses in this table are followed. Any #security scripts in the table are called.

This way you have complete power over what gets called.

To check out the script in Frontier that dispatches incoming messages, jump to traps.Unix.scpt. (To the Mac-savvy -- what's happening is that the command-line tool frontier is sending an Apple event to Frontier itself.)

Things your scripts should do

Your scripts can take multiple parameters, of course. On the command line they're separated by spaces. (Use quotes as necessary.)

Every parameter your script gets is a string -- so if you're expecting a number, or something other than a string, you'll have to coerce it.

Also, for scripts intended to be returned to a user, it's wise to add a \n (line feed) to the end of your result. (This is not done automatically, since there may be times you don't want a line feed added.)

No waiting

If you want to call into Frontier but you don't want to wait for the reply, use the -n switch, like this:

./frontier -n examples.getStateName 41

Frontier will execute the script, but the result won't be returned.

What you can do

Since other scripting languages -- such as Perl and Python -- can execute command-line strings, this means they can call into Frontier too.

Imagine, for instance, a Perl CGI, running behind Apache, that calls Frontier to render a page. Or a Python script that populates a Frontier guest database.
