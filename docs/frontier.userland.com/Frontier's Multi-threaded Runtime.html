Frontier's Multi-threaded Runtime

Frontier's multi-threaded runtime allows background processes to run once a second, minute, hour or daily, or respond to incoming TCP requests, or COM or Apple Event messages.

Background processes

Agent scripts run continually, as frequently as once per second.

On the Macintosh, agent scripts can use the IdleTime Init to run tasks when the machine has been idle for a certain period of time. (Screen saver functionality.)

Scheduled scripts are agents that run at a specific time.

Responders

Frontier's web server is built around a plug-in architecture called Responders.

Here's a screen shot of the responders table. Every HTTP request is routed thru this table.

You can write your own responders (please do!), but we've included a high-level responder, called mainResponder, starting in Frontier 6.0, that handles many of the things that modern dynamic sites want to do.

Threading verbs

The Frontier environment is completely multi-threaded. Your scripts generally don't need to worry about threading issues. The thread verbs allow your scripts to launch new threads, to communicate between code running in different threads, and to stop the execution of other threads. The semaphore verbs allow you to coordinate access of shared resources between several concurrent threads.

Low-level TCP services

Inetd is a framework for writing tcp servers in Frontier.

This page links to other pages on this site with information about TCP scripting in Frontier.

Frontier has a complete set of tcp-level verbs.

Frontier COM server

On Windows you can run Frontier scripts in response to incoming COM requests.

Frontier Apple Event server

On the Macintosh, scripts residing in system.verbs.traps table run when Frontier receives an incoming Apple Event. This is the equivalent of the user.com table on the Macintosh. (There is no specific page on the site covering system.verbs.traps.)
