Desktop Scripts

Desktop scripts are a convenient way to make the power of Frontier available right on your desktop. On this page we'll examine a desktop script so you can see how they work. We'll show you how to create and save a desktop script. Then we'll discuss how you can customize desktop scripts.

Our focus here is to give you an overview of desktop scripts, it's not critical that you understand the details of every script. Remember, to get details on any verb, look it up in DocServer.

An Overview of Desktop Scripts

As files that live on disk, desktop scripts appear to the user much like stand-alone applications. However, they require Frontier to be available, making them a cross between a document and an application.

If you double-click a desktop script in the Explorer or Finder -- or even open one from Frontier's File menu -- the script will run. So, how do you edit it? There's a trick: when you double-click on the file, hold down the control key (on Macs it's the command key) and continue holding it until the script is open in Frontier. (If you let go before your operating system passes control to Frontier, Frontier will just run the script since it has no way of knowing that you held the key down briefly.)

Count HTML Files desktop script.

Like most desktop scripts, this script finds out what file it was launched through calling window.getFile (this). It uses the built-in file.folderFromPath verb to pop out one level, so it can loop over all the files in the folder that contains it. This means you can move the script to a different folder to get it to count the HTML files in that folder.

The count of HTML files is initialized to 0, and then the script sets up a loop that goes thru all the files contained in the folder, to infinite depth. When it encounters a file with a name that ends with ".html" or ".htm," it adds one to the counter.

When the loop is complete, a message is created, saying how many matching files it found. With UserTalk's case statement, it produces a syntactically correct English statement and displays it using Frontier's built-in dialog.notify verb.

Creating and saving desktop scripts

If you want to try out the above script, choose New->Script from Frontier's file menu. A new, empty script-editing window appears.

New, empty script window.

Type in the script as it appears in the first picture. When you're finished, choose Save as Runnable from the File menu. Choosing Save as Runnable lets Frontier know this is a desktop script -- meaning that it should be run instead of opened for editing when you double-click it.

After you've saved your script, close the window it's in. Then switch to the Explorer or Finder and double-click on your script. Frontier will come to the front and your script will execute.

In Windows, desktop scripts are saved with an .ftds file suffix. On Macs, desktop scripts have the type code 'FTds.' The icon for desktop scripts is a cowboy riding a horse.

Customizing this script

This desktop script is useful as is, but we obviously couldn't anticipate everything you might want to do. Since this is a script, you can change it to fit your needs. We'll look at two possible changes to these scripts here; realize that these examples are simply designed to get your creative juices flowing about things you might do with these desktop scripts.

Counting other kinds of files

The most obvious way you could customize this example would be to look for files other than HTML files. You can do so by opening the script in Frontier (while holding the control key) and making these simple changes:

Replace "HTML" in the comment on line 2 with the type of files you want to find.

Instead of looking for files that end with ".html" or ".htm," change that line to look for files that end with, for instance ".gif."

In the last part of the script, change "HTML" to the name of the file type you're counting.

Tips

Before you give a desktop script to another user to work with, we recommend that you test it on at least one system other than your own to check for errors such as including a reference to a specific hard disk.

Tip for Macintosh users: if the window for the folder or volume to which you save the desktop script is open when you save the script, you may have to close the folder and then re-open it for the desktop script to be able to be launched with a double-click. This limitation is one of the quirks of the Finder.
