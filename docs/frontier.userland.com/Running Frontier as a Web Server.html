Running Frontier as a Web Server

Dynamic Web Server

In addition to being a powerful content management system, thru the Website Framework, Frontier is also a standard HTTP 1.1 server, allowing for a smooth and high-level connection between web browsers and content that's rendered thru templates and with macros.

In other words, with Frontier as a web server, all the benefits of managed content can be applied to dynamic sites with personalized presentation.

You can also run Frontier behind a static web server, such as Microsoft IIS or WebSTAR. In these situations, Frontier does not handle the HTTP connections directly. This could be desirable if you want all HTTP traffic to come in thru a single piece of software.

mainResponder

Frontier's server architecture is built around an architecture called responders.

In Frontier 6, released in April 1999, we built a higher level architecture called mainResponder that implements high-level dynamic features such as membership, preferences, storage, discussion groups, virtual domains, subscriptions, a search engine, calendars, cookies, logging, news sites, file uploads.

This page guides you thru the technical specifications and howtos that help you set up a mainResponder-based server for your site.

Requirements

Unless otherwise stated, all documentation assumes that you're using the current version of Frontier, which as of August 1999, is version 6.0. You must also have a server to experiment with. A full-time net connection is not required to test, but to deploy it certainly is.

Getting started

Follow the instructions in the Read Me.html file in the Frontier folder to be sure Frontier's web server is fully installed, turned on and running.

The Guest Databases folder

The Guest Databases folder is the shell for your web presence. It's at the top level of your Frontier folder, and contains three sub-folders, www, ops and apps.

The files and sub folders and object databases you put in the www folder are accessible over the web.

The ops folder contains logs, backups, membership info, the operational files for your site that are not visible thru HTTP.

The apps folder contains software and a single configuration file, config.root, that's created by mainResponder the first time it runs. By convention each app in the apps folder "owns" a branch of config.root, and it stores all its data there.

For more information on guest databases, see this introduction.

Basic Information

discuss.root is where all messages in the Discussion Group are stored.

members.root is where information about each member is stored.

user.databases controls which guest databases are automatically opened when Frontier starts up.

Server Attributes allow you to control how objects are served and config.mainResponder.globals is where you control the defaults for all sites served by Nirvana.

mainResponder and Time explains the standard data structures and navigation routines for time-based information in Nirvana Server.

mainResponder and Searching shows you how to to set up Frontier's built-in search engine to index content coming in thru Discussion Groups.

frontierStartupCommands.txt is a text file containing a script that runs when Frontier starts up.

Subscriptions

You can publish a guest database and allow other people to subscribe to changes made to the guest database. It uses the same mechanism as updates to Frontier.root.

Logging

The user.log table contains Frontier's logging preferences.

config.mainResponder

config.root, in the apps sub-folder of the Guest Databases folder, is like the user table for apps that run in the Guest Databases apps folder.

Each app should stake out a table with the same name, following the pattern of mainResponder. Then store all your user preference settings in that table, exactly as you would do with the user table for code that runs in Frontier.root.

There are currently six areas of configuration: callbacks, domains, globals, prefs, search and urls. They are explained on the pages linked to each of the following items:

config.mainResponder.callbacks, is a table that contains scripts allowing you to customize and extend Frontier's performance as a web server.

config.mainResponder.domains. This is where virtual hosting is implemented. Each item in this table points to the root of a virtual domain.

config.mainResponder.globals is a table containing the default values of the server attributes for all content served by mainResponder.

config.mainResponder.prefs is a table of preference settings for code running in mainResponder.root.

config.mainResponder.search a table containing values that configure the search engine.

Each of the items in config.mainResponder.urls provides a name for a URL. The instant you change one of these URLs, the pages that mainResponder generates will change.
