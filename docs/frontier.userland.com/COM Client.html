UserLand Frontier

COM Client

Overview

Beginning with Frontier 6.0, Windows users can call Active Scripting Engine scripts from Frontier.

Active Scripting Engine languages include VBScript, JScript (Microsoft JavaScript), PerlScript, and others.

The main benefit to calling scripts in these languages is that they have support for COM scripting. You can, for instance, script Microsoft Excel with VBScript, or script Eudora with JScript, and so on.

Requirements

You will need the Microsoft Script Control installed on your system. It's a free download, from Microsoft's scripting site.

Though it's not required, it's a good idea to also install Windows Script Host (WSH), which you can also get from the above site. With WSH installed you can script the Windows shell. (See the DocServer docs on the winShell verbs.)

Your First Active Script

Let's create a VBScript script that takes one parameter and returns a result.

It's just an example, so it won't do anything fancy: it just takes a number, multiplies it by 10, and returns the result. The script looks like this: 

Function Main (num)
    Main = num * 10
End Function

Create an outline at workspace.vbExample, and type the above script into the outline.

Then create a new Frontier script at workspace.callVbExample. The Frontier script should look like this: 

local (scriptCode = string (workspace.vbExample))
local (result)
result = com.callScript (scriptCode, "VBScript", "Main", {10})
dialog.notify (result)

Run the script -- you should see a dialog box whose text is "100."

What's going on

The first line gets the contents of your VBScript script from the outline. The scriptCode variable is a string containing the VBScript script.

The second line just declares a local variable where the script will store the result.

The third line calls the com.callScript verb. This verb takes four parameters. The first parameter is the script to execute, the second parameter is the language the script is in, the third parameter is the name of the function or subroutine to call in the script, and the last parameter is a list of parameters to pass to the script that's being called.

You can read more about com.callScript in DocServer.

In a nutshell, the third line sets the result variable to the result of calling the VBScript script.

The last line simply displays the result in a dialog box.

Handling errors

Try modifying the Frontier script above so that instead of passing the number, you pass a string. Edit the third line to read:

result = com.callScript (scriptCode, "VBScript", "Main", {"foo"})

Then run the script. You'd expect an error, because you can't multiple "foo" by 10.

An Error Info window will appear, explaining the error that occurred. It will read something like: Can't execute this script because the Script Control reports: "Type mismatch: 'num'. The error code is: 13. The type of error is: Microsoft VBScript runtime error. The line number of the error is: 2"

Errors are reported with as much information as possible needed to track down the error, even down to the line number at which the error occurs.

Scripting the Windows Shell

You can script lots of applications, including the Windows shell. In fact, we've provided some glue -- the winShell verbs -- to get you started. You can use the winShell verbs without knowing anything about com.callScript. But if you're interested in writing your own Active Scripting Engine scripts, then these make good examples.

For example, jump to winShell.createUrlShortcut. It looks something like this (though actually it has more comments): 

on createUrlShorcut (path, url)
    local (s = string (winShell.data.scripts.createUrlShortcut))
    com.callScript (s, "VBScript", "Main", {path, url})
    return (true)

This is a Frontier script that takes two parameters. The first thing it does is put into s the contents of the outline at winShell.data.scripts.createUrlShortcut -- which is a VBScript script that looks like this: 

Sub Main (filename, url)
    Dim shell
    Dim urlLink
    
    Set shell = createObject ("Wscript.Shell")
    
    Set urlLink = shell.CreateShortcut (filename)
    
    urlLink.TargetPath = url
    urlLink.Save
End Sub

It's outside the scope of this HowTo explain to everything about how VBScript works, so a summary will suffice: this script gets an instance of the Shell object, which is a COM object. Then it calls the CreateShortcut method, which creates a shortcut object, which the script stores a reference to in the urlLink variable. Then the TargetPath property is set, then the shortcut is saved.

This script doesn't return a result, though it could have.

The point is: this is an example of scripting an application in Windows. This same model can be used to drive Excel, Word, Eudora, and any other Windows applications that support COM scripting.

The second point is: you can create Frontier glue for your Active Scripting Engine scripts, so they're re-usable. To use the winShell.createUrlShortcut verb from other Frontier scripts, all you do is call winShell.createUrlShortcut with path and url parameters -- it's just like calling any other Frontier verb.

(Note: scripting the Windows Shell does require that WSH is installed. See the Requirements section above.)

Calling back to Frontier

Frontier is itself a COM server. This means that Frontier can be scripted through VBScript and other languages.

This means that your VBScript can call back to Frontier to run scripts while the VBScript script is running.

Any script that's in the user.com table can be called from Active Scripting Engine scripts.

Here's an example:

Create a Frontier script at user.com.getUserName, which reads: return (user.prefs.name)

Create another Frontier script at user.com.setHelloString, which reads: 

on setHelloString (s)
    wp.newTextObject (s, @temp.helloString)
    edit (@temp.helloString)
    return (true)

Create an outline at workspace.callbackExample that reads: 

Function Main
    Dim name
    Dim helloString
    Dim x
    name = Frontier.getUserName ()
    helloString = "Hello " + name + "!"
    x = Frontier.setHelloString (helloString)
    Main = "The hello string has been set."
End Function

Create a script at workspace.callCallbackExample that reads: 

local (s = string (workspace.callbackExample))
local (result = com.callScript (s, "VBScript", "Main", {}))
dialog.notify (result)

When you run workspace.callCallbackExample, it calls the VBScript script, which calls back into Frontier: it calls user.com.getUserName and user.com.setHelloString. Instead of referring to "user.com," the VBScript script refers to "Frontier."

When you run the script, you should see a new wp-text object at temp.helloString open in a window, and you should see a dialog box that reads, "The hello string has been set."

This example shows you how to get information from Frontier, store information, and have Frontier perform actions.
