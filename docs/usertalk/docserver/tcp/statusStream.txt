#title "tcp.statusStream"Syntax	tcp.statusStream (stream, adrBytesPending)Params	stream is a stream reference returned by "tcp.openStream", or a listener reference returned by "tcp.listenStream" (legacy shared-ID-space overload).	adrBytesPending is the address of a variable that will be filled with the number of bytes waiting to be read on this connection.Action	Checks the status of a TCP/IP connection, or of a listener.Returns	One of the following strings:		CLOSED: the connection is closed; this stream reference is now invalid		OPEN: the connection is open but there is no data waiting to be read		DATA: the connection is open and there is data waiting to be read		INACTIVE: the stream reference is invalid or unknown (e.g. never allocated, already freed via tcp.closeStream, listener already torn down via tcp.closeListen, or the input is neither a known stream nor a known listener)		CLOSING: the connection is being closed; you cannot read from or write to the stream		UNKNOWN: the stream is in the middle of connecting (handshake in progress), or its state is otherwise indeterminate		LISTENING: the input is a listener reference (not a stream) and that listener is currently running. This is the legacy listener-ID overload, used by scripts such as inetd.isDaemonRunning to check whether a listener is still alive.		STOPPED: the input is a listener reference whose accept loop has been signalled to stop but whose registry slot has not yet been freed. This is a transient state visible only during a narrow window inside tcp.closeListen (between the running=false signal and the slot being nulled); a single-threaded caller will normally see INACTIVE instead, because tcp.closeListen does not return until the slot has been freed.ExamplesNotes	This verb obsoletes NetEvents.statusStream.	In addition to stream references, this verb also accepts listener references returned by tcp.listenStream. This dual-purpose behavior preserves the legacy shared-ID-space convention used by inetd.isDaemonRunning() and similar scripts to check whether a listener is still active. A LISTENING return therefore means the input ID matched a still-running listener, not a stream.
