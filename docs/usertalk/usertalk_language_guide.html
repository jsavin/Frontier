Language Overview

UserTalk is Frontier's native scripting language, designed around the object database system. It features a hybrid architecture where approximately 50% of functionality is implemented in UserTalk scripts and 50% in C kernel implementations.

Key Characteristics:
  • Object-Oriented: Built around Frontier's object database system
  • Dynamic Typing: Variables have no type until assigned
  • Cross-Platform: Supports both Macintosh and Windows
  • JITC: Uses Just In Time Compilation for performance
  • Database-Centric: Deep integration with .root database files

Syntax & Structure

Basic Syntax Rules

  • UserTalk is an imperative language - programs are sequences of commands
  • Commands are executed consecutively from start to end
  • Every command either performs an assignment or calls a verb
  • Indentation is significant for control structures

Variable Declaration

local (var1, var2, var3) // Declare multiple local variables local (myString = "Hello") // Declare with initial value global (sharedVar) // Declare global variable persistent (configValue) // Declare persistent variable

Assignment

myVariable = 42 // Basic assignment myString = "Hello, World!" // String assignment myArray = {1, 2, 3, 4, 5} // Array assignment myTable = new table // Object creation and assignment

Control Structures

Repetition (Looping)

For Loops

// Counter-based iteration for i = 1 to 5 msg (i) clock.waitSeconds (1) // List iteration for element in finderMenu.getSelectionList () dialog.alert (element)

While Loops

while not file.endOfFile (f) msg (file.readLine (f)) clock.waitSeconds (0.1)

Fileloop Structure

// Basic file iteration fileloop (f in path) msg (file.fileFromPath (f)) // With depth parameter fileloop (f in path, infinity) // Visit all files at all levels msg (file.fileFromPath (f))

Loop Structure

loop msg (i) i = i + 1 if i > 5 break // Exit the loop

Decisions (Branching)

If/Else Structure

if answer > 6 msg ("Big family!") else msg ("Not such a big family!")

Case Structure

case letter "a" "e" msg ("Vowel") "b" msg ("Consonant") else msg ("This example isn't very thorough.") // Equivalent to else-if case true temperature < minimum dialog.alert ("Too cold.") temperature > maximum dialog.alert ("Too hot.") else dialog.notify ("Delicious porridge.")

Error Handling

// Prevention strategy if file.exists (f) file.delete (f) // Status checking if file.open (f) theLine = file.readLine (f) file.close (f) // Try/else structure try file.delete (f) else dialog.alert ("Could not delete file")

Data Types

UserTalk supports 28 different data types. Here are the most commonly used ones:

Data Type Description Example
stringType Text data with full 255-character support "Hello, World!"
numberType Numeric values (integers and floating-point) 42 or 3.14159
booleanType True or False values true or false
addressType Object database references @table.subtable.object
arrayType Heterogeneous lists with zero-based indexing {1, "two", 3.0, true}
recordType Key-value associative storage ["name": "John", "age": 30]
tableType Object database tables new table
outlineType Hierarchical data structures new outline
scriptType Executable UserTalk code new script
wptextType Rich text with formatting new wptext

Operators

Arithmetic Operators

a = 10 + 5 // Addition: 15 b = 10 - 3 // Subtraction: 7 c = 4 * 6 // Multiplication: 24 d = 15 / 3 // Division: 5 e = 17 % 5 // Modulo: 2 f = 2 ^ 3 // Exponentiation: 8

Increment/Decrement

i = 1 i++ // Increment: i becomes 2 i-- // Decrement: i becomes 1

Comparison Operators

a == b // Equal to a != b // Not equal to a < b // Less than a <= b // Less than or equal to a > b // Greater than a >= b // Greater than or equal to

Logical Operators

a and b // Logical AND a or b // Logical OR not a // Logical NOT

String Concatenation

firstName = "John" lastName = "Doe" fullName = firstName + " " + lastName // "John Doe"
Important: UserTalk uses the + operator for string concatenation, not the & operator used in some other languages.

Verbs & Functions

Verb Syntax

verb (param1, param2) // Standard call with parameters verb () // Call with no parameters verb (param2: val2) // Named parameter override adrVerb^ () // Dereferenced address call

Verb Implementation

Verbs in UserTalk are organized in tables within the database hierarchy:

system.verbs.builtins.db.open // Full path to verb script
Verb Architecture:
  • Table Hierarchy: Verbs live in script objects within database tables
  • JITC: Scripts use Just In Time Compilation by the runtime
  • Kernel Integration: Scripts call C kernel implementations for core functionality
  • Hybrid Model: Many verbs are UserTalk scripts that call other verbs

Database Integration

Address References

@table.subtable.object // Address reference local (adrCreateMessage = @manilaSuite.discuss.createMessage) adrCreateMessage^ (param1, param2) // Dereference and call local (adrTable = @someTable) // Address to table adrTable^ // Dereference table

Object Reference Syntax

path.to.parentOfMyObject.["My Object"] // Object with special characters tableName.objectName // Standard object reference parentTable.["Object With Spaces"] // Object with spaces in name local (myObjectName = "Object Name"); tableName.[myObjectName] // Dynamic reference

Database Lifecycle

db.new (filepath) // 1. Create database db.open (filepath, false) // 2. Open for access db.setValue (filepath, "path", value) // 3. Modify data db.save (filepath) // 4. Save changes db.close (filepath) // 5. Close database

Practical Examples

Hello World

msg ("Hello, World!") // Simple message display

File Processing

local (filePath = "example.txt") if file.exists (filePath) local (fileHandle) if file.open (filePath, fileHandle) local (line) while not file.endOfFile (fileHandle) line = file.readLine (fileHandle) msg (line) file.close (fileHandle) else dialog.alert ("Could not open file") else dialog.alert ("File does not exist")

Database Operations

local (dbPath = "myDatabase.root") local (myTable = new table) // Add some data table.addColumn (myTable, "name", "string") table.addColumn (myTable, "age", "number") table.addRow (myTable, ["John", 30]) table.addRow (myTable, ["Jane", 25]) // Save to database db.new (dbPath) db.open (dbPath, false) db.setValue (dbPath, "people", myTable) db.save (dbPath) db.close (dbPath)

Web Server Example

local (port = 8080) webServer.start (port) // Handle requests on webServer.request (request) local (response = "HTTP/1.1 200 OK\r\n") response = response + "Content-Type: text/html\r\n\r\n" response = response + "

Hello from UserTalk!

" return (response)
Best Practices:
  • Always use local() for variables unless you need global scope
  • Check return values from verbs that can fail
  • Use try/else for error handling when appropriate
  • Close files and databases when you're done with them
  • Use meaningful variable names and add comments for complex logic
