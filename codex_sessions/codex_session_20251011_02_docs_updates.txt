• High-Level Patterns

  - Global runtime state is still scattered across module-scope globals. Common/source/lang.c:68 maintains interpreter flags (flbreak, flscriptrunning, etc.)

  - Capability gating for UI-only verbs exists as an informal adapter. Common/source/shell_api_headless.c:14 installs a headless implementation and tests/
    headless_shell.c:1 provides matching stubs. Codifying this as a “Capability Adapter” pattern would help both documentation and future UIServices work (per
    planning/adr/0002-ui-boundary-ports-and-adapters.md:1).
  - Memory management still depends on classic handle semantics. Common/source/portable_handles.c:65 shows the portable reimplementation that keeps stable handle
    pointers with relocatable buffers. Treat this as a first pattern card—“Portable Handle Allocator”—and link back to docs/portable_handles.md:1 for details.
  - Headless behavior is coordinated by policy docs (planning/no_ui_linkage_policy.md:1, planning/headless_stubbed_behavior_matrix.md:1) but the code relies
    on scattered #ifdef FRONTIER_PORTABLE blocks (see Common/source/lang.c:28). Documenting a “Portability Facade” pattern would help engineers understand how
    platform shims and tests relate.
  - The project already treats Pascal bigstring values as the lingua franca across modules (constants in Common/source/lang.c:68). A “Length-Prefixed String”
    pattern entry should flag the upcoming UTF-8 transition (planning/phase4/string_and_text_modernization.md) and explain safe interop rules.
