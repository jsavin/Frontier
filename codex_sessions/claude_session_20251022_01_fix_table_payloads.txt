  Problem Diagnosis

  - frontier-cli was crashing with a heap-buffer-overflow when trying to load Frontier.root
  - The crash occurred in unmergehandles during table unpacking

        32 +  ## Table Payload Format (v6 and v7 Databases)
        33 +  
        34 +  Table payloads are stored using a two-level merged handle structure created by `tablepacktable()` and unpacked by `tableunpacktable()` (`Common/source/tablepack.c`):
        35 +  
        36 +  ### Modern (v7) Two-Level Merged Format
        37 +  ```
        38 +  [outer_size: 4 bytes, big-endian]     ← outer merge prefix
        39 +    [inner_merged_table]                 ← created by hashpacktable()
        40 +    [formats_data]                       ← optional table formatting info
        41 +  ```
        42 +  
        43 +  Where `inner_merged_table` is itself a merged handle:
        44 +  ```
        45 +  [inner_size: 4 bytes, big-endian]     ← inner merge prefix
        46 +    [header: 16 bytes]                   ← tydisktablerecord
        47 +    [records: 10 bytes each]             ← tydisksymbolrecord array
        48 +    [sentinel: 10 zero bytes]            ← marks end of records
        49 +  [strings]                              ← Pascal string pool
        50 +  ```
        51 +  
        52 +  The table header (`tydisktablerecord`, 16 bytes total):
        53 +  - `version` (2 bytes): table disk version (0x03 for v5.0+)
        54 +  - `sortorder` (2 bytes): sort order flags
        55 +  - `timecreated` (4 bytes): creation timestamp
        56 +  - `timelastsave` (4 bytes): last save timestamp
        57 +  - `flags` (4 bytes): XML and other flags
        58 +  
        59 +  Each symbol record (`tydisksymbolrecord`, 10 bytes):
        60 +  - `ixkey` (4 bytes, big-endian): offset into string pool for symbol name
        61 +  - `valuetype` (1 byte): type of the value (string, int, table, etc.)
        62 +  - `version` (1 byte): record version
        63 +  - `data` (4 bytes): value data or offset into string pool

        66 +  
        67 +  Legacy v6 databases store table payloads in Pascal-era format WITHOUT merge prefixes:
        68 +  ```
        69 +  [header: 16 bytes]                    ← tydisktablerecord
        70 +  [strings]                             ← Pascal string pool
        71 +  [records: 10 bytes each]              ← tydisksymbolrecord array
        72 +  [sentinel: 10 zero bytes]             ← all zeros
        73 +  ```
        74 +  
        75 +  Key differences from modern format:

        77 +  2. **Strings before records** – the order is reversed (legacy has strings first, modern has records first in the inner merge)
