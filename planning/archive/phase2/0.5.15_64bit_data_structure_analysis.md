## **Overview**

This document analyzes all data structures stored in `.root` files that need 64-bit conversion. Understanding these structures is crucial for:
1. **Database Migration**: Converting legacy 32-bit formats to 64-bit
2. **UserTalk Compiler**: Understanding what objects can be stored/retrieved
3. **UserTalk Interpreter**: Knowing how to handle different data types
4. **Backward Compatibility**: Ensuring old files can still be read

## **Core Database Structures**

### **1. Database Header (`tydatabaserecord`)**

**Current 32-bit Structure (116 bytes on 64-bit systems):**
```c
typedef struct tydatabaserecord {
    unsigned char systemid;        // 1 byte
    unsigned char versionnumber;   // 1 byte
    dbaddress availlist;          // 8 bytes (long long)
    short oldfnumdatabase;        // 2 bytes
    short flags;                  // 2 bytes
    dbaddress views[ctviews];     // 24 bytes (3 * 8 bytes)
    Handle releasestack;          // 8 bytes (void*)
    long fnumdatabase;            // 8 bytes (long)
    long headerLength;            // 8 bytes (long)
    short longversionMajor;       // 2 bytes
    short longversionMinor;       // 2 bytes
    union {
        char growthspace[50];     // 50 bytes
        struct {
            dbaddress availlistblock;  // 8 bytes
            handlestream availlistshadow; // 8 bytes
            boolean flreadonly;         // 1 byte
        } extensions;
    } u;
} tydatabaserecord;
```

**Proposed 64-bit Structure (88 bytes):**
```c
typedef struct tydatabaserecord_64 {
    unsigned char systemid;        // 1 byte
    unsigned char versionnumber;   // 1 byte
    dbaddress availlist;          // 8 bytes (long long)
    short oldfnumdatabase;        // 2 bytes
    short flags;                  // 2 bytes
    dbaddress views[ctviews];     // 24 bytes (3 * 8 bytes)
    Handle releasestack;          // 8 bytes (void*)
    long fnumdatabase;            // 8 bytes (long)
    long headerLength;            // 8 bytes (long)
    short longversionMajor;       // 2 bytes
    short longversionMinor;       // 2 bytes
    union {
        char growthspace[22];     // 22 bytes (reduced for 64-bit alignment)
        struct {
            dbaddress availlistblock;  // 8 bytes
            handlestream availlistshadow; // 8 bytes
            boolean flreadonly;         // 1 byte
        } extensions;
    } u;
} tydatabaserecord_64;
```

**Key Changes:**
- **`dbaddress`**: `long` (4 bytes) → `long long` (8 bytes)
- **`Handle`**: `void*` (4 bytes) → `void*` (8 bytes)
- **`long`**: 4 bytes → 8 bytes
- **Total Size**: 88 bytes → 80 bytes

### **2. Database Address Type (`dbaddress`)**

**Current:**
```c
typedef long dbaddress;  // 32-bit address
```

**Proposed:**
```c
typedef long long dbaddress;  // 64-bit address
```

**Impact:**
- **File Size**: Larger address space for bigger databases
- **Memory Usage**: More memory for address storage
- **Performance**: Potential performance impact with larger addresses

## **UserTalk Language Structures**

### **3. Value Records (`tyvaluerecord`)**

**Current Structure:**
```c
typedef struct tyvaluerecord {
    tyvaluetype valuetype;        // 2 bytes
    byte fltmpdata: 1;           // 1 bit
    byte fltmpstack: 1;          // 1 bit
    byte flformalval: 1;         // 1 bit
    byte fldiskval: 1;           // 1 bit
    tyvaluedata data;            // Union of various types
} tyvaluerecord;
```

**Value Data Union (`tyvaluedata`):**
```c
typedef union tyvaluedata {
    boolean flvalue;              // 1 byte
    byte chvalue;                // 1 byte
    short intvalue;              // 2 bytes
    long longvalue;              // 4 bytes → 8 bytes
    unsigned long datevalue;      // 4 bytes → 8 bytes
    tydirection dirvalue;        // 4 bytes
    OSType ostypevalue;          // 4 bytes
    Handle stringvalue;           // 4 bytes → 8 bytes
    hdlstring addressvalue;      // 4 bytes → 8 bytes
    Handle binaryvalue;           // 4 bytes → 8 bytes
    short tokenvalue;            // 2 bytes
    struct tytreenode **codevalue; // 4 bytes → 8 bytes
    Handle externalvalue;         // 4 bytes → 8 bytes
    Point pointvalue;            // 8 bytes (unchanged)
    Rect **rectvalue;            // 4 bytes → 8 bytes
    Pattern **patternvalue;      // 4 bytes → 8 bytes
    RGBColor **rgbvalue;         // 4 bytes → 8 bytes
    Fixed fixedvalue;            // 4 bytes
    float singlevalue;           // 4 bytes
    double **doublevalue;        // 4 bytes → 8 bytes
    Handle objspecvalue;         // 4 bytes → 8 bytes
    hdlfilespec filespecvalue;   // 4 bytes → 8 bytes
    Handle aliasvalue;           // 4 bytes → 8 bytes
    OSType enumvalue;            // 4 bytes
    struct tylistrecord **listvalue; // 4 bytes → 8 bytes
    struct tylistrecord **recordvalue; // 4 bytes → 8 bytes
    dbaddress diskvalue;         // 4 bytes → 8 bytes
} tyvaluedata;
```

**Key Changes:**
- **All `long` types**: 4 bytes → 8 bytes
- **All `Handle` types**: 4 bytes → 8 bytes
- **All pointer types**: 4 bytes → 8 bytes
- **`dbaddress`**: 4 bytes → 8 bytes

### **4. Tree Nodes (`tytreenode`)**

**Current Structure:**
```c
typedef struct tytreenode {
    tytreetype nodetype;         // 2 bytes
    tyvaluerecord nodeval;       // Variable size
    struct tytreenode **link;    // 4 bytes → 8 bytes
    unsigned long lnum;          // 4 bytes → 8 bytes
    byte charnum;               // 1 byte
    byte ctparams;              // 1 byte
    struct tytreenode **param1, **param2, **param3, **param4; // 16 bytes → 32 bytes
} tytreenode;
```

**Key Changes:**
- **`link` pointer**: 4 bytes → 8 bytes
- **`lnum`**: 4 bytes → 8 bytes
- **Parameter pointers**: 16 bytes → 32 bytes

**Current Structure:**
```c
typedef struct tyhashnode {
    struct tyhashnode **hashlink;    // 4 bytes → 8 bytes
    struct tyhashnode **sortedlink;  // 4 bytes → 8 bytes

    byte fllocked: 1;               // 1 bit

    byte flunresolvedaddress: 1;     // 1 bit

```

**Key Changes:**
- **`hashlink`**: 4 bytes → 8 bytes
- **`sortedlink`**: 4 bytes → 8 bytes

## **Migration Strategy**

### **1. Version Detection**

**Database Header Check:**
```c
if ((**hdb).versionnumber <= 6) {
    // Use 32-bit structure sizes
    use_32bit_format = true;
} else if ((**hdb).versionnumber >= 7) {
    // Use 64-bit structure sizes
    use_32bit_format = false;
}
```

### **2. Structure Size Validation**

**Current Validation:**
```c
assert(sizeof(tydatabaserecord) == 88);  // 32-bit
```

**New Validation:**
```c
if (use_32bit_format) {
    assert(sizeof(tydatabaserecord) == 88);
} else {
    assert(sizeof(tydatabaserecord) == 80);  // 64-bit
}
```

### **3. Address Conversion**

**32-bit to 64-bit Address Conversion:**
```c
dbaddress convert_address_32_to_64(dbaddress old_addr) {
    if (old_addr == nildbaddress) {
        return nildbaddress;
    }
    // Convert 32-bit address to 64-bit
    return (dbaddress)old_addr;
}
```

**64-bit to 32-bit Address Conversion:**
```c
dbaddress convert_address_64_to_32(dbaddress new_addr) {
    if (new_addr == nildbaddress) {
        return nildbaddress;
    }
    // Validate address fits in 32 bits
    if (new_addr > 0xFFFFFFFF) {
        // Error: address too large for 32-bit format
        return nildbaddress;
    }
    return (dbaddress)new_addr;
}
```

## **UserTalk Language Impact**

### **1. Value Types**

**All UserTalk value types need 64-bit support:**
- **Numbers**: `long` → `long long` (64-bit integers)
- **Addresses**: `addressType` → 64-bit addresses
- **Handles**: All handle types → 64-bit pointers
- **Strings**: No change (already variable length)
- **Tables**: Hash table structures → 64-bit pointers
- **Scripts**: Tree node structures → 64-bit pointers

### **2. Address Resolution**

**UserTalk Address Syntax:**
```usertalk
@table.object           // 64-bit address resolution
new (tableType, @table) // 64-bit address creation
nameOf (adrObject)      // 64-bit address dereferencing
```

### **3. Cross-Database References**

**Full Path References:**
```usertalk
["/path/to/database.root"].table.object  // 64-bit address across databases
```

## **Performance Considerations**

### **1. Memory Usage**

**Increased Memory Requirements:**
- **Addresses**: 2x memory for address storage
- **Pointers**: 2x memory for pointer storage
- **Large integers**: 2x memory for `long` types

### **2. File Size Impact**

**Database File Sizes:**
- **Small databases**: Minimal impact
- **Large databases**: Significant size increase
- **Hash tables**: 2x size for bucket arrays

### **3. Performance Impact**

**Potential Performance Issues:**
- **Cache misses**: Larger structures may cause more cache misses
- **Memory bandwidth**: More data to transfer
- **Address calculations**: 64-bit arithmetic may be slower on some systems
