## Commit Message

```
fix: correct v7 database header structure alignment (90-byte header with proper padding)

Fixed critical structure alignment bug in v7 database header that was causing the
views array to be misaligned. Both tydatabaserecord and tydatabaserecord_64
structures now include explicit 2-byte padding after the flags field to ensure
proper 8-byte alignment of the views array at offset 16.

Changes:
- Added explicit 2-byte padding to both database record structures
- Updated structure sizes: tydatabaserecord 116→118, tydatabaserecord_64 88→90
- Updated all size assertions and validation comments
- Added runtime validation for structure layout
- Created test_struct_layout.c to verify offsets at compile time
- Fixed unrelated function signature bug in kernel_verbs_headless.c

Why this fix is critical:
The #pragma pack(2) directive was forcing 2-byte alignment, causing the views
array to be at offset 14 instead of 16. This caused misalignment of 64-bit
addresses and incorrect BE64 serialization.

Documentation:
- Updated all database-related planning and technical docs
- Added v7_structure_alignment_fix.md with comprehensive technical reference
- Added documentation_updates_2025-12-04.md with change summary
- Verified cross-platform implications and alignment requirements

Verification:
✅ Structure layout test passes
✅ Views array at correct offset 16
✅ Database header is 90 bytes
✅ frontier-cli parses v7 headers correctly
```
