# Plan: Fix Integration Test Failures (67 multi-worker + state leak)

**Created:** 2026-02-16
**Status:** Planned, not yet started

## Context

67 tests fail in the standard 8-worker batch run. Running single-worker batch reveals 755 failures due to state leaking between evaluations in the long-lived process — the `clearContext` fix in PR #428 only reset error globals, not all contaminating state. This plan addresses both: (A) test-level fixes for the 67 real failures, and (B) deeper `clearContext` improvements to reduce state leaks.

### Key Discovery: fileMenu.new() Dual Mode

`fileMenu.new()` has two modes (see `docs/usertalk/docserver/fileMenu/new.txt`):
1. **Type mode**: `fileMenu.new(scriptType)` — creates an in-memory external, returns its address
2. **Path mode**: `fileMenu.new("/path/to/file.root7")` — creates a guest database file on disk

## Part B: Deeper Fixes

### B1: State Leak in clearContext (755→67 gap)
The `clearContext` in PR #428 resets `langerrordisable`, `langerrorlogdisable`, and `fllangerror`. But 755 failures in single-worker mode vs 67 in 8-worker mode shows massive additional state contamination.

**Action:** Investigate what additional state needs resetting in `handle_clear_context()`. Candidates:
- Database/guest database state (open databases from previous test)
- Target/window state
- Global variable state beyond the REPL variables table
- Thread state
- TCP/network state
- Any globals set during xml, fileMenu, or other verb execution

**Approach:** Run single-worker batch, identify which test files cause cascading failures in subsequent files, then trace the contaminating state.

### B2: Uncatchable Verb Errors (~20 tests across multiple categories)
**Root cause:** Certain C verbs produce fatal errors that bypass try/else. Verified for: fileMenu.new (existing file), fileMenu.open (nonexistent), xml.compile (bad XML), table.sortby (no target), string.mid (out of bounds), tcp.listenStream (bad params).

Script-level errors (undefined var, divide by zero) ARE catchable. The issue is in how certain verb implementations report errors — they likely call a fatal error function instead of returning false.

**Action:** Investigate the error reporting path for these verbs. The fix is likely making them return false (catchable) instead of calling a fatal abort.

**Impact:** Fixing this one issue would resolve ~20 tests across Categories A4, A7, A10, A11.
