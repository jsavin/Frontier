## Current Status
After QuickTime elimination, we still have critical header inclusion order issues preventing compilation.

## Identified Issues

### 1. Header Inclusion Order Conflicts
- Frontier headers (`standard.h`, `shelltypes.h`) are being included before system headers
- This causes `unknown type name` errors for `RgnHandle`, `Pattern`, `ControlHandle`, `MenuHandle`
- System headers provide these types, but they're not available when Frontier headers are processed

### 2. ARC Compatibility Issues
- `NSAutoreleasePool` is not available in ARC mode (`-fobjc-arc`)
- Need to replace with `@autoreleasepool` block or remove ARC requirement

### 3. Type Redefinition Conflicts
- `frontier_compat.h` is trying to redefine types already defined by system headers:
  - `DialogRef` (Carbon vs our definition)
  - `ATSUFontID` (ATSUI vs our definition)  
  - `FSRefPtr` (CarbonCore vs our definition)
  - `AppleEventPtr` (AE vs our definition)

### 4. Incomplete Type Definitions
- `FSRef` and `HFSUniStr255` are forward-declared but not fully defined
- This causes "incomplete type" errors in `shelltypes.h`

## Fix Strategy

### Step 1: Fix Header Inclusion Order
- Ensure `frontier_compat.h` is included before any Frontier headers
- Modify `main_modern.m` to include system frameworks first, then compatibility layer, then Frontier headers

### Step 2: Fix ARC Compatibility
- Remove `NSAutoreleasePool` usage from `main_modern.m`
- Use `@autoreleasepool` block instead

### Step 3: Clean Up Type Definitions
- Remove redundant type definitions from `frontier_compat.h` that conflict with system headers
- Only define types that are truly missing

### Step 4: Fix Incomplete Types
- Ensure `FSRef` and `HFSUniStr255` are properly defined before use

## Next Actions
1. Update `main_modern.m` header inclusion order
2. Fix ARC compatibility in `main_modern.m`
3. Clean up `frontier_compat.h` type definitions
4. Test compilation after each fix
