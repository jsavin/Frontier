# Phase 0.3: ARM Architecture Audit Results

## **Critical Issues Found**

### **1. Alignment Pragmas (CRITICAL)**

#### **Problem: Extensive use of `#pragma options align=reset`**
Found **67 instances** across the codebase:

```c
// Found in multiple files:
#pragma options align=reset  // ❌ Resets alignment to compiler default
```

**Files affected**:
- `scripts.c` (3 instances)
- `langops.c`, `dbstats.c`, `player.c` (1 each)
- `langregexp.c`, `langerrorwindow.c`, `langlist.c` (1 each)
- `timedate.c` (2 instances)
- `oppopup.c`, `tableexternal.c`, `langdialog.c` (1 each)
- And 50+ more files...

**Issues**:
- **Alignment assumptions** - May assume x86 alignment behavior
- **Structure padding** - May change on ARM64
- **Database compatibility** - .odb files may assume specific alignment
- **Cross-platform issues** - Different alignment on different architectures

#### **Problem: Mac68k alignment pragmas**
```c
// Found in:
#pragma options align=mac68k  // ❌ Mac68k-specific alignment
```

**Files affected**:
- `MoreFilesExtras.c`
- `uisharing.c`
- `menusharing.c`

**Issues**:
- **Legacy alignment** - Mac68k alignment is not ARM64 compatible
- **Structure layout** - May cause alignment faults on ARM64

### **2. PowerPC-Specific Code (HIGH)**

#### **Problem: PowerPC assembly and timing code**
```c
// From FastTimes.c
#if TARGET_CPU_PPC
// PowerPC-specific timing code
static Boolean gUseRTC = false;  // Real Time Clock
static Boolean gUseTBR = false;  // Time Base Register
#endif
```

**Issues**:
- **PowerPC assembly** - Not compatible with ARM64
- **Timing mechanisms** - RTC and TBR are PowerPC-specific
- **Performance optimizations** - May not work on ARM64

#### **Problem: PowerPC timing intrinsics**
```c
// PowerPC-specific timing code
#define RTCToNano(w) ((double) (w).hi * 1000000000.0 + (double) (w).lo)
#define WideTo64bit(w) (*(UInt64 *) &(w))
```

**Issues**:
- **PowerPC registers** - RTC and TBR are PowerPC-specific
- **Timing accuracy** - May not work correctly on ARM64
- **Performance impact** - Fallback to slower methods on ARM64

### **3. Memory Layout Assumptions (MEDIUM)**

#### **Problem: Direct memory access**
```c
// From FastTimes.c
#define MyLMGetTicks() (*(volatile UInt32 *) 0x16A)  // ❌ Direct memory access
```

**Issues**:
- **Hardcoded addresses** - 0x16A is Mac OS specific
- **Memory model** - May not work on ARM64
- **Security** - Direct memory access may be blocked on modern systems

#### **Problem: Structure alignment assumptions**
```c
// From various files - structures assume specific alignment
typedef struct {
    // ... fields with assumed alignment
} SomeStruct;
```

**Issues**:
- **Alignment requirements** - ARM64 may have different alignment
- **Structure size** - May change due to padding
- **Database compatibility** - .odb files assume specific layouts

### **4. Architecture-Specific Optimizations (MEDIUM)**

#### **Problem: Performance optimizations**
```c
// From FastTimes.c comments
// "On PowerPC machines, we try several methods:
//   * DriverServicesLib is available on all PCI PowerMacs
//   * The PowerPC 601 has a built-in "real time clock" RTC
//   * Later PowerPCs have an accurate "time base register" TBR"
```

**Issues**:
- **PowerPC-specific** - These optimizations don't exist on ARM64
- **Performance degradation** - May fall back to slower methods
- **Timing accuracy** - May be less accurate on ARM64

## **ARM-Specific Requirements Analysis**

### **Memory Alignment**
- **ARM64**: 8-byte alignment for pointers, 4-byte for int
- **x86_64**: 8-byte alignment for pointers, 4-byte for int
- **Current code**: Assumes various alignments via pragmas

### **Calling Conventions**
- **ARM64**: AAPCS64 (ARM Architecture Procedure Call Standard)
- **x86_64**: System V AMD64 ABI
- **Current code**: No assembly found, so calling conventions should be fine

### **SIMD Instructions**
- **ARM64**: NEON instructions
- **x86_64**: SSE/AVX instructions
- **Current code**: No SIMD found, so no issues

### **Atomic Operations**
- **ARM64**: Different atomic primitives
- **x86_64**: Different atomic primitives
- **Current code**: No atomic operations found
