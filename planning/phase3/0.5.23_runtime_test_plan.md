## Objective

Define the first wave of unit and integration tests that exercise the real
Frontier runtime without relying on the old stub layer. The goal is to gain
confidence in core functionality (database I/O, scripting pipeline, critical
verbs) while keeping the harness lightweight enough to run on macOS, Linux, and
Windows.

## Scope (Phase 0.5.23)

1. **Database Smoke Tests**
   - Open/create `.root` files via public APIs (`dbopenfile`, `dbnew`).
   - Read/write primitive values using the authentic database engine.
   - Validate address/handle behaviour on the new portable allocator.

2. **Scripting Engine Tests**
   - Compile and execute simple UserTalk snippets via `langrunstring` and
     `langrunstringnoerror`.
   - Verify parameter passing and value coercion for core types (strings,
     numbers, booleans).

3. **Verb Sanity Checks**
   - Identify a small set of verbs with minimal external dependencies (e.g.
     string utilities) and ensure they can be invoked through the runtime.

4. **Infrastructure**
   - Reuse the existing `tests/` directory.
   - Use a single executable (`core_tests`) with sub-test functions rather than a
     complex harness.
   - Keep the build dependency list minimal (no Carbon, QuickTime, or UI).

## Follow-up Phases

- **Phase 0.5.24:** Broaden coverage to table verbs and more complex database
  scenarios (nested tables, outlines).
- **Phase 0.5.25:** Stress test migration/64-bit conversion logic once the new
  database path lands.

## Implementation Notes

- Tests should include headers via `frontier.h` so platform abstractions apply
  consistently.
- For now, link only the modules required for the tested functionality (database
  + language engine) to keep the build fast.
- Capture test results in `tests/README.md` and update the planning log when new
  suites land.
- Link the headless harness against `tests/headless_shell.c` to satisfy
  references to `shellvisittypedwindows`/`shellerrormessage` without dragging in
  the full UI.
- Extracted the header-detection helpers into `Common/source/db_format.c` and
  added `tests/db_format_tests.c` so the 32→64-bit conversion path now has a
  runnable unit test in headless mode (`make db_format_tests`).
- Track a follow-up task to replace the legacy PCRE dependency used by
  `langregexp.c` with a modern regex engine so headless builds no longer rely on
  the Carbon-era port.

## Risks & Dependencies

- Many runtime/verb entry points still rely on UI/window globals. Attempting to
  exercise them headlessly will require either stubbing those callbacks or
  introducing a minimal UI shim.
- The database layer touches the handle allocator extensively; ensure the new
  portable implementation mirrors legacy semantics to avoid subtle regressions.
- Several core modules import `shell.h` purely for utilities like
  `shellerrormessage` and `shellvisittypedwindows`. Tests can avoid the full UI
  stack by providing headless replacements for those routines, but that wiring
  must be completed before database smoke tests can link.
- `langcallbacks` currently expect a UI host to install error/reporting
  handlers. A headless test harness needs to populate the struct with safe
  defaults (e.g., log-only error reporting) to keep the interpreter from
  dereferencing null pointers.
