# ADR-015: Verb Registration Consolidation

## Status

Accepted

## Date

2026-02-14

## Context

The headless verb registration system had two completely separate codepaths:

1. **Test binary** (`tests/Makefile`) compiled `Common/source/kernel_verbs_headless.c` — a manually-maintained file with `init_efp_*` functions that called each processor's `initverbs()`.
2. **Production CLI** (`frontier-cli/Makefile`) used `generated/kernel_verbs_init.c` — auto-generated by `parse_kernelverbs.py`, filtered by a hardcoded `HEADLESS_REGISTERED` whitelist set.

This created a fragile three-step workflow: create the headless verb file, add to `headless_verbs.mk`, and add to the `HEADLESS_REGISTERED` set in `parse_kernelverbs.py`. If any step was missed, tests could pass (using the manual codepath) while the production CLI silently failed to register the processor.

The `--analyze` mode (designed to auto-detect registered processors from C source) was unreliable — it missed processors guarded by `#ifdef` in the RC file, and it actively overrode intentional exclusions like `webserver`.

### Approaches Considered

**A. Fix the analyzer to handle `#ifdef` blocks**
- Fragile: every new preprocessor pattern requires analyzer updates
- Doesn't solve the dual-codepath divergence problem

**B. Maintain `HEADLESS_REGISTERED` as source of truth**
- Still requires manual updates in Python when adding C files
- Easy to forget, with silent failures

**C. Derive registration from `headless_verbs.mk` filenames (chosen)**
- The filename convention is 100% consistent: `headless_{processor}_verbs.c` → `{processor}initverbs()`
- Single source of truth: if the file compiles, the processor is registered
- Fail-safe: forgetting to add to `.mk` causes a build error, not a silent runtime failure

## Decision

Both test binary and production CLI now use `generated/kernel_verbs_init.c`, auto-generated from processor names extracted from `tests/headless_verbs.mk` filenames.

The workflow is now two steps:
1. Create `tests/headless_{processor}_verbs.c`
2. Add it to `tests/headless_verbs.mk`

A small `EXCLUDED_PROCESSORS` blocklist in `parse_kernelverbs.py` handles processors that must not be registered as EFPs (currently only `webserver`, whose EFP stub shadows `builtins.webserver` script implementations).

## Consequences

### Positive
- **Eliminates silent failures**: If a file isn't in `.mk`, it won't compile — immediate build error
- **Single codepath**: Test and production use identical registration, by definition
- **Simpler workflow**: Two steps instead of three
- **Fixes webserver bug**: The analyzer was overriding the intentional webserver exclusion

### Negative
- `Common/source/kernel_verbs_headless.c` is now dead code (kept for reference, no longer compiled)
- The `--analyze` mode is demoted to reporting-only (still useful for diagnostics)
