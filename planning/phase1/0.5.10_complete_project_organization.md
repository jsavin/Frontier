├── databases/                     # Database files

│   └── Guest Databases/          # User databases

## Organization Rationale

### **1. Cross-Platform Compatibility**
- **`tests/`**: Universal test framework accessible to all build targets
- **`samples/`**: Test data available across all platforms
- **`planning/`**: Documentation accessible from any build system

### **2. Clear Separation of Concerns**
- **`databases/`**: All .root files in one location
- **`app_resources/`**: Application-specific resources separated from source
- **`docs/`**: All documentation centralized
- **`bin/`**: Future location for compiled binaries

### **3. Scalability**
- **Build Systems**: Each build target has its own directory
- **Resources**: Platform-specific resources organized by app
- **Documentation**: SDK and user docs separated

## Updated File Organization

Based on user feedback and future relevance, the organization has been refined:

### **Application Resources** (Frontier-specific)
```
app_resources/Frontier/
├── frontierStartupCommands.txt    # Startup commands (Frontier-specific)
├── Extras/                        # Frontier-specific extras
│   └── keepFrontierRunning/      # Keep Frontier running utilities
├── Appearance/                    # UI appearance files (if needed)
│   └── Icons/                   # Icon assets
└── [existing Frontier resources]  # Icons, plists, bundles
```

### **Intentionally Excluded** (Low Priority/Obsolete)
- **DLLs**: Ancient Windows DLLs (odbc.dll, regexcarbon.dll) - not relevant for modern development
- **Altivec Support**: PowerPC-specific optimizations - obsolete for ARM/x86_64
- **ODBC**: Legacy database connectivity - not needed for modern refactoring
- **Shell executables**: Low priority - will be addressed in future phases

### **Documentation** (partially complete)
