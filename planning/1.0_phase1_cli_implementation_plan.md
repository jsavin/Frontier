# Frontier Phase 1: CLI-Based UserTalk Invocation Implementation Plan

## Overview

Phase 1 focuses on implementing a command-line interface (CLI) for UserTalk script execution, enabling Frontier to run UserTalk scripts from the command line without requiring the full GUI environment. This builds upon the solid foundation established in Phase 0.

## Current State Analysis

### ✅ Phase 0 Accomplishments
- **Build System**: Universal binary support (x86_64 + ARM64)
- **Database Migration**: 64-bit format with backward compatibility
- **Testing Framework**: Comprehensive test suite for database operations
- **UserTalk Analysis**: Complete understanding of language architecture

### 🔧 Key Technical Foundation
- **Database System**: `Common/source/db.c` with 64-bit migration support
- **UserTalk Runtime**: `Common/source/lang.c` and `Common/source/langevaluate.c`
- **Build System**: `build_Xcode_modern/Makefile` for universal compilation
- **Language Architecture**: Hybrid C/UserTalk with JITC compilation

## Phase 1 Goals

### Primary Objectives
1. **CLI Interface**: Command-line tool for UserTalk script execution
2. **Database Integration**: CLI access to Frontier database operations
3. **Script Execution**: Direct UserTalk script compilation and execution
4. **Network Protocol**: HTTP/WebSocket interface for remote execution
5. **Integration Testing**: Validate CLI with real UserTalk scripts

### Secondary Objectives
1. **Error Handling**: Robust error reporting for CLI environment
2. **Performance**: Optimized execution for headless operation
3. **Documentation**: CLI usage documentation and examples
4. **Testing**: Comprehensive test suite for CLI functionality

## Technical Architecture

### 1. CLI Application Structure

```
frontier-cli/
├── main.c                 # CLI entry point
├── cli_parser.c          # Command-line argument parsing
├── cli_executor.c        # UserTalk script execution
├── cli_database.c        # Database operations for CLI
├── cli_network.c         # HTTP/WebSocket server
└── cli_utils.c           # Utility functions
```

### 2. Core Components

#### A. CLI Parser (`cli_parser.c`)
- Parse command-line arguments
- Support multiple execution modes
- Handle script files and inline code
- Process database operations

#### B. UserTalk Executor (`cli_executor.c`)
- Initialize UserTalk runtime environment
- Compile and execute UserTalk scripts
- Handle script results and errors
- Manage memory and cleanup

#### C. Database Interface (`cli_database.c`)
- Open/close Frontier databases
- Execute database operations
- Handle database migration
- Provide database query interface

#### D. Network Server (`cli_network.c`)
- HTTP server for remote execution
- WebSocket support for real-time communication
- REST API for database operations
- Security and authentication

### 3. Execution Modes

#### Mode 1: Direct Script Execution
```bash
frontier-cli script.usertalk
frontier-cli -e "db.open('test.root'); db.getValue('test.root', 'path')"
```

#### Mode 2: Database Operations
```bash
frontier-cli -d test.root -q "db.getValue('path')"
frontier-cli -d test.root -m migrate
```

#### Mode 3: Network Server
```bash
frontier-cli --server --port 8080
frontier-cli --websocket --port 8081
```

## Technical Implementation Details

### 1. CLI Argument Structure

```c
typedef struct {
    char* script_file;           // Script file to execute
    char* inline_script;         // Inline script code
    char* database_file;         // Database file to operate on
    char* query;                 // Database query to execute
    int port;                    // Network server port
    boolean verbose;             // Verbose output
    boolean debug;               // Debug mode
    boolean server_mode;         // Run as network server
    boolean websocket_mode;      // Enable WebSocket support
} cli_options_t;
```

### 2. UserTalk Execution Context

```c
typedef struct {
    hdltreenode hcode;          // Compiled script tree
    hdlhashtable hcontext;      // Execution context
    tyvaluerecord vresult;      // Execution result
    boolean flsuccess;          // Success flag
    char* error_message;        // Error message
} usertalk_execution_t;
```

### 3. Database CLI Interface

```c
typedef struct {
    char* db_path;              // Database file path
    boolean flreadonly;         // Read-only mode
    hdldatabaserecord hdb;      // Database handle
    boolean flopen;             // Open status
} cli_database_t;
```

### 4. Network Server Structure

```c
typedef struct {
    int port;                   // Server port
    boolean flhttp;             // HTTP server enabled
    boolean flwebsocket;        // WebSocket enabled
    void* http_server;          // HTTP server handle
    void* websocket_server;     // WebSocket server handle
} network_server_t;
```
