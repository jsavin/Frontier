# Phase 0.2: 64-bit Data Type Audit Plan

## Priority: HIGH (Prerequisite for header compatibility)

### **Why This Must Come First**

The 64-bit data type audit is foundational because:
1. **Header conflicts stem from data type issues** - We need to understand what types are problematic
2. **Systematic approach** - Audit the entire codebase for 64-bit compatibility issues
3. **Safer than header hacking** - Identify issues without breaking compilation
4. **Informs compatibility strategy** - Knowing the data type issues helps create better solutions

## **Audit Categories**

### **1. Integer Type Audit**
**Target**: All integer types (int, long, size_t, ptrdiff_t)

**Search Patterns**:
```bash
# Find all integer type usage
grep -r "int\|long\|size_t\|ptrdiff_t" Common/source/ Common/headers/
grep -r "typedef.*int\|typedef.*long" Common/headers/
```

**Critical Issues to Find**:
- `long` used where `int` should be (32-bit vs 64-bit)
- `int` used for pointer arithmetic
- `size_t` vs `unsigned int` confusion
- Pointer-to-integer conversions

### **2. Pointer Arithmetic Audit**
**Target**: All pointer arithmetic operations

**Search Patterns**:
```bash
# Find pointer arithmetic
grep -r "pointer\|ptr\|address" Common/source/
grep -r "sizeof\|offsetof" Common/source/
```

**Critical Issues to Find**:
- Pointer-to-integer conversions without proper casting
- Assumptions about pointer size
- Array indexing with integer types
- Memory layout assumptions

### **3. Structure Packing Audit**
**Target**: All structure definitions

**Search Patterns**:
```bash
# Find structure definitions
grep -r "struct\|typedef struct" Common/headers/
grep -r "pack\|align\|offset" Common/headers/
```

**Critical Issues to Find**:
- Structure alignment assumptions
- Packed structures that assume 32-bit alignment
- Union types with size assumptions
- Bit field layouts

### **4. Bitwise Operations Audit**
**Target**: All bitwise operations

**Search Patterns**:
```bash
# Find bitwise operations
grep -r "& \| \| \| ^\|<<" Common/source/
grep -r "bit\|mask\|flag" Common/source/
```

**Critical Issues to Find**:
- Bit shifts with hardcoded values
- Mask operations assuming 32-bit integers
- Flag bit definitions
- Endianness assumptions

### **5. Handle Type Audit**
**Target**: All Handle type usage

**Search Patterns**:
```bash
# Find Handle usage
grep -r "Handle\|hdl\|handle" Common/source/ Common/headers/
grep -r "typedef.*Handle" Common/headers/
```

**Critical Issues to Find**:
- Handle size assumptions
- Handle-to-pointer conversions
- Memory management with handles
- Handle alignment requirements

## **Audit Process**

### **Step 1: Automated Scanning**
```bash
# Create audit scripts
./audit_integer_types.sh
./audit_pointer_arithmetic.sh
./audit_structure_packing.sh
./audit_bitwise_operations.sh
./audit_handle_types.sh
```

### **Step 2: Manual Review**
- Review each identified issue
- Categorize by severity (Critical/High/Medium/Low)
- Document specific problems and solutions

### **Step 3: Fix Planning**
- Create fix strategies for each category
- Prioritize fixes by impact
- Plan compatibility layers

## **Expected Findings**

Based on the compilation errors, we expect to find:

### **High Priority Issues**
1. **Handle type size assumptions** - Handles were 32-bit in Classic Mac OS
2. **Pointer arithmetic with int** - Should use size_t or ptrdiff_t
3. **Structure alignment** - May assume 32-bit alignment
4. **Bit field layouts** - May assume 32-bit word size

### **Medium Priority Issues**
1. **Integer type mismatches** - long vs int usage
2. **Array indexing** - May use int instead of size_t
3. **Memory allocation** - Size calculations may be wrong

### **Low Priority Issues**
1. **Endianness assumptions** - May assume little-endian
2. **Alignment requirements** - May assume 4-byte alignment
